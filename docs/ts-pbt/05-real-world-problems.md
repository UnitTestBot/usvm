# Полный разбор проблем, найденных на реальном TypeScript-коде

> **Статус документа, 2026-07-22.** Это каталог наблюдений и исторической
> динамики, а не текущая инструкция запуска. Часть перечисленных проблем уже
> закрыта в `caelmbleidd/ts-pbt-roadmap-integration`. Актуальный checkpoint,
> проверенные команды и незавершённые интеграционные задачи находятся в
> [`14-continuation-guide.md`](14-continuation-guide.md).

> Каталог всех дефектов и несоответствий, обнаруженных при прогоне гибридного
> анализа (PBT + targeted символьное исполнение) на реальных опенсорс-проектах.
> Каждая запись: симптом с цифрами → корень → демонстрация на реальном коде →
> статус фикса → измеренный эффект.
>
> Корпуса: TheAlgorithms/TypeScript (maths/sorts/search/dynamic_programming),
> loiane/javascript-datastructures-algorithms (src, 307 методов),
> basarat/typescript-collections (src/lib). Сводные замеры — в §Результаты.

## Класс A: движок убивает состояния (андер-аппроксимация)

### A1. Любой неразрешённый вызов убивал всё после себя

**Симптом.** 155 из 172 непокрытых символьных targets умирали за <100 мс
(не таймаут!); целые методы с нулевым покрытием, включая тривиальные числовые.

**Демонстрация** (TheAlgorithms `maths/factorial.ts`):

```ts
export const factorial = (num: number): number => {
  if (num < 0 || !Number.isInteger(num)) {   // <- Number.isInteger не в сцене
    throw new Error('only natural numbers are supported')
  }
  return num === 0 ? 1 : num * factorial(num - 1)
}
```

Лог движка: `Could not resolve method: ::isInteger` → `scope.assert(falseExpr)`
на 5-м шаге → все 4 ветки метода недостижимы. Guard-вызовы такого рода стоят
в начале почти каждой функции реального кода.

**Корень.** Три места в `TsInterpreter.visitVirtualMethodCall` отвечали на
неразрешённый вызов убийством состояния — тотальная андер-аппроксимация.

**Фикс.** `ts-interpreter-fixes @ a15dc8fd`: мок вместо убийства (по образцу
уже существовавшего фоллбека для конструкторов) + отдельная строка лога
`"Mocking an unresolved call: … (over-approximation)"` на каждый мок —
остаточная овер-аппроксимация измерима. Unsound-достижимость фильтруется
конкретным replay в гибридном пайплайне.

**Эффект.** maths: symbolic-only 34.8→63.1% веток; hybrid 64.0→83.0%.

### A2. Инкремент/декремент валил резолвер

**Симптом.** `IllegalStateException: Not supported --year` — все состояния в
циклах с `x--` гибли (ts-frontend-провайдер).

**Демонстрация** (типичный корпусный код): `while (!isLeapYear(y)) { --y; }`.
ts-frontend эмитит value-часть `y := --y` с явным writeback; jacodb конвертит
оба оператора только в Pre*-классы; резолвер движка на них падал.

**Фикс.** `ts-interpreter-fixes @ b690eb25`: Pre* = ToNumber(arg)±1,
Post* = старое значение. Тесты — на программно построенном IR (ArkAnalyzer
эти узлы не эмитит вовсе — раскладывает в `x := x + 1`).

## Класс B: движок отвечает неверно (овер-аппроксимация/несоответствие JS)

### B1. Идиома truthiness `x != 0` и её двойная NaN/undefined-дыра

**Симптом.** Дифф-оракул: `And.andOfUnknown(0, undefined)` — движок 21, JS 0
(undefined «истинен»); после первого фикса — `andOfUnknown(NaN, x)` — движок
верно 11, а конкретный интерпретатор 0 (NaN «истинен» уже у него).

**Корень.** Фронтенды понижают `if (x)` в `x != 0` (AA) / `x != false`
(ts-frontend) — байт-в-байт неотличимо от настоящего loose-сравнения. Численное
прочтение дырявое с двух сторон: `ToNumber(undefined)=NaN != 0 → true`, и
`NaN != 0 → true`, хотя оба значения falsy.

**Демонстрация** (usvm-ts sample `operators/And.ts`):

```ts
andOfUnknown(a: any, b: any): number {
  const res = a && b;
  if (a) { ... } else if (Number.isNaN(a)) { // JS: NaN сюда, движок было — мимо
    if (b) { if (Number.isNaN(res)) return 11; } ...
```

**Фикс.** Двумя симметричными коммитами: движок
(`7c5a6a7c`+`befd79f6`) — `!=` против литерального 0/false резолвится через
`mkTruthyExpr` для ВСЕХ видов операндов; конкретный интерпретатор
(`7733c2e8` в ts_pbt) — тот же контракт. Важная деталь: идиома использует
только `!=` (отрицание — swap successors), поэтому `==` сохранил literal
семантику. `And.andOfUnknown` проходит дифф против починенного движка.

**Методологическая ценность.** Оракул поймал дыру у ОБОИХ исполнителей, в
противоположных зонах (ref vs fp) — витрина triple-oracle подхода.

### B2. `+` на ссылках аппроксимирован численно

**Симптом.** `Add.addUnknownValues(null, {})`: движок NaN (идёт в concretely
недостижимую ветку `res != res`), JS — `"null[object Object]"` → 42.

**Статус.** Задокументировано, в whitelist диффа; фикс требует строковой
теории — отложен (движковый бэклог).

### B3. Реляционные операторы на смешанных fake-сортах

**Симптом.** `Less.lessUnknown(false, 0.0)`: движок true, JS false
(`Lt.onBool = !lhs && rhs` вместо ToNumber-коэрции).

**Статус.** whitelist + бэклог движка.

### B4. Рекурсия `StrictEq.resolveFakeObject ↔ resolveBinaryOperator`

**Симптом.** StackOverflow в логах корпусных прогонов на сравнениях
fake-объектов; состояния гибнут. Бэклог движка.

### B5. Гонка stop/collect в targeted-режиме

**Симптом.** `REACHED_TARGET`-коллектор никогда не отдавал состояния:
`stopOnTargetsReached` срабатывает в момент пропагации (до терминации), а
коллектор смотрит только терминированные; вдобавок в `TsMachine` коллектор
стоит в цепочке observers раньше `ReachabilityObserver`.

**Фикс** (ts_pbt, SymbolicPhase): собственный захват состояния в момент
пропагации + `TsTestResolver.resolveInputs` для не-терминированных состояний.

## Класс C: фронтенды выдают некорректный/неоднозначный IR

### C1. Дрейф порядка successors у if — инверсия всех веток

**Симптом.** «Pre-existing» падения тестов usvm-ts (`Add`: invariants violated;
reachability: «unreachable stmt reached»), плюс дифф-расхождения на каждом
методе с ветвлением.

**Корень.** DTO-контракт: AA сериализует if-successors как (false, true),
jacodb-лифт нормализует в (true, false). Локальная dev-ветка AA (`lipen/usvm`)
эмитит порядок, несовместимый с нормализацией пиннованной, — после лифта
**каждая ветка каждого метода инвертирована**. Контракт нигде не проверяется.

**Демонстрация** (`operators/Less.ts`, лоуринг `lessUnknown`):
блок `if (a < b)` → successors `[check-b<a, return-true]` — под одним
прочтением семантика исходника, под другим — противоречие (недостижимые ветки).

**Фикс-процесс.** Все прогоны пиннованы на `neo/2025-09-03` (worktree),
документировано в notes 02; дифф-оракул ловит такие дрейфы за минуты.

### C2. Постфиксный инкремент лоурится неверно (ArkAnalyzer)

**Симптом.** Тест `const old = x++` невыполним ни при какой семантике движка.

**Демонстрация** (AA-лоуринг):

```
x := x + 1
old := x        // old получает НОВОЕ значение!
diff := x - old // всегда 0, JS даёт 1
```

**Статус.** Баг лоуринга AA; задокументирован в фикстуре
`samples/operators/IncDec.ts` движковой ветки; тест-кейс сознательно исключён.

### C3. Фантомные классы от path-alias импортов

**Симптом.** `instance method: lessThan on VObject(@/comparator: Comparator)` —
резолюция уходила в класс-пустышку.

**Корень.** `import Comparator from '@/comparator'` порождает в сцене класс
с сигнатурой, но без тел — и он затенял настоящий одноимённый класс при
поиске по имени (метод-резолюция, инстанцирование в генераторе).

**Фикс** (`26b2507c`, ts_pbt): ранжирование одноимённых классов по
«содержательности» (тела методов + поля) в CallResolver и генераторе;
фронтенд-фидбек: алиасы стоит резолвить на стороне ts-frontend.

### C4. Тип поля «функция», а код зовёт на нём методы объекта

**Симптом.** ~1k executions: `lessThan on VFunction(RedBlackTree::#removeNode…)`.

**Демонстрация** (loiane `10-tree`): в IR поле объявлено функциональным типом
(`#compareFn: CompareFn<T>`), а код вызывает **методы объекта Comparator**:
`this.#compareFn.lessThan(a, b)`. Генератор честно следует объявленному типу
и подставляет функцию → каждый такой вызов честно Unsupported.

**Статус.** Несоответствие типизации ts-frontend (фидбек jacodb#361);
эвристики генератора замазали бы симптом, а не причину.

### C5. SpreadElement — непрозрачный RawEntity

**Симптом.** Крупнейший остаточный Unsupported-bucket PBT (1883 executions с
12 сайтов): `...args` сериализуется как `UnsupportedValue {kindName:
"SpreadElement"}` — исполнить честно невозможно. Фидбек ts-frontend.

### C6. Идиома `!= 0` неотличима от настоящего сравнения

См. B1: это свойство IR (оба фронтенда); предложение для jacodb#361 —
выделенный truthiness-узел ConditionExpr снял бы неоднозначность и в движке,
и в интерпретаторе.

## Класс D: экстракция входов из символьных состояний

### D1. Резолвер падал на не тронутых путём полях

**Симптом.** 47 из 68 достигнутых targets на datastructures вообще не доходили
до replay: `resolveInputs` бросал «UnresolvedSort should be represented by a
fake object» для полей input-объектов, которые путь не читал.

**Корень + фикс** (`20e43862`): такие поля не являются input-обязательствами
(path-minimal семантика) — деградация в TsUnknown; конверсия replay пропускает
нерезолвимое (подмена undefined безопасна: replay валидируется по ребру —
ложное подтверждение невозможно, возможна только потеря).

### D2. Ключи fake-объектов не совпадали + циклы графов объектов

**Симптом.** Остаточные 2 падения — StackOverflow на циклических списках
узлов; lookup fake-объектов по сырому символьному ref, тогда как bookkeeping
хранит model-evaluated ключи.

**Фикс** (`97ae9c52`): cycle guard в resolveTsClass + поиск по обоим
представлениям ключа. Падения резолюции: 47 → 2 → **0**.

### D3. Остаточная replay-дивергенция = цена моков (система работает)

**Симптом.** 66 reached / 1 replay-confirmed на datastructures.

**Диагноз** (после D1/D2 каждая дивергенция объяснима): пути идут через
замоканные вызовы (`Object.prototype.hasOwnProperty.call(this.items, k)` в
MySet/Dictionary) — модель законно не ограничивает поля → вход не определяет
ветку → replay корректно отказывает в подтверждении. Это ровно та
овер-аппроксимация, которую replay и должен фильтровать; число — измеренная
цена остаточных моков. Разблокируется моделированием field-membership
(движковый бэклог, ср. path-minimal объекты).

## Класс E: пробелы конкретного интерпретатора (закрыты по данным)

Гистограмма причин Unsupported (теперь фича отчёта) вела каждую итерацию:

| Находка | Объём | Фикс |
|---|---|---|
| HOF массивов с колбэками (`reduce`/`map`/`some`) | 312 | invoker + map/filter/forEach/reduce/some/every/find/findIndex/sort |
| `ptr_call` (вся рекурсия arrow-функций) | сотни | алиасы из file-init + dynamic VFunction |
| `new Array(n)` давал объект, не массив | 58+ | Array/Map/Set конструкторы |
| Колбэки/компараторы генерились мусором | 2318 | VFunction над методом сцены нужной арности |
| `JSON.stringify` | 748 | полная ES-семантика (undefined/functions omitted, циклы кидают) |
| глобальный `isFinite`, `split`, `localeCompare`, … | ~700 | интринсики |
| Вызов функции из поля `this.#cmp(a,b)` | ~10 targets | field-function dispatch |

**Эффект суммарно** (datastructures PBT): Unsupported 13436 → 6718 (project
scene) → **4216**; ветки 62.5 → 66.7%.

### E1. Кросс-файловые цели при per-file сценах

**Симптом.** Доминирующий bucket: `lessThan` 46, `greaterThan` 24, класс
`Stack` 29 — всё определено в соседних файлах проекта.

**Фикс** (`d1bd5136`): batch-CLI грузит корпус в одну project-сцену
(резолюция имя-ориентированная — заработало без правок резолверов);
`--file-scenes` для сравнения. Эффект: Unsupported −50%, символьная фаза
57.2→59.8% при вдвое меньшем per-target таймауте.

## Класс F: точные модели builtin'ов вместо моков (баланс аппроксимаций)

Частотные замеры (полные логи, оба корпуса) показали: неразрешённые вызовы =
кросс-файл (→E1) + горячие builtin'ы + честно немоделируемое. Горячие
смоделированы точно в fp-теории (`b68e7aaf`, `3df3c83a`):

- `Math.abs` (208 на одном maths!), `floor/ceil/trunc` (round-to-integral),
  `round` = floor(x+0.5) по JS, `sqrt`, `min/max` с JS-семантикой NaN
  (NaN если ЛЮБОЙ аргумент NaN — отличие от IEEE minNum/maxNum);
- `Number.isInteger` (55) / `isSafeInteger` / `isFinite` — с обработкой
  дискриминаторов fake-объектов;
- `console.*` = side-effect-free undefined;
- конструктор `Array`: `new Array(n)` — настоящий массив с fork'ом на
  валидность длины.

**Метрика баланса — replay-confirmed**: unconstrained-мок даёт модели,
невоспроизводимые конкретно; точная модель — воспроизводимые.
maths symbolic-only: replay-confirmed 41 (до всего) → 66 → 83 → **87**.

## Выводы

1. **Главные враги на реальном коде — не path explosion**, а: (а) обрыв
   анализа на первом неразрешённом вызове, (б) контрактные несоответствия
   фронтендов (порядок веток, идиома truthiness, типизация полей),
   (в) видимость сцены (кросс-файл).
2. **Дифф-оракул конкретного интерпретатора окупает себя многократно**:
   восемь подтверждённых дефектов движка/фронтендов, включая симметричную
   дыру у самого оракула.
3. **Честный учёт (`Unsupported`-гистограмма, лог каждого мока,
   replay-confirmed)** превращает «плохие проценты» в конкретные,
   приоритизируемые причины — каждая итерация этой работы выбиралась по
   данным, а не по интуиции.
